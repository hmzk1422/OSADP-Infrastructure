Changes to enable YAML-driven execution mode selection (mode: playback -> select PlaybackBackend)
=================================================================================================

These changes let you set `mode: playback` in `settings.yaml` and have the Rust
entry point build a `PlaybackBackend` (accelerated historical replay) instead of
`LiveTestBackend` (paper) or `LiveTradeBackend` (venue).

IMPORTANT: Nothing in this patch automatically reads settings.yaml or starts
playback. You still must call `ManagerEngine::from_settings(...)` from your
binary/entry point after loading the YAML. The wiring from a YAML file to that
call is the responsibility of the entry point. This patch makes the configuration
path typed, validated, and recoverable (no panics).

/// YAML-deserializable execution settings. Mirrors [`ExecutionMode`] variants
/// but uses only plain data so it can be loaded from `settings.yaml`.
///
/// Changing `mode` to `playback` (and setting `acceleration`) makes
/// [`ManagerEngine::from_settings`] build a `PlaybackBackend` that replays
/// merged Parquet through the same `SimEngine` paper trading uses.
#[derive(Clone, Debug, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct ExecutionSettings {
    /// `live_test`, `live_trade`, or `playback`.
    pub mode: String,
    /// Replay speed multiplier (playback only). 1.0 = real time, 100 = 100x.
    #[serde(default = "default_acceleration")]
    pub acceleration: f64,
    /// Half-spread applied at execution, in bps.
    #[serde(default)]
    pub spread_bps: Option<f64>,
    /// Adverse slippage applied at execution, in bps.
    #[serde(default)]
    pub slippage_bps: Option<f64>,
    /// Taker fee per fill notional, in bps.
    #[serde(default)]
    pub fee_bps: Option<f64>,
    /// Capital allocated to strategies with no explicit allocation.
    #[serde(default)]
    pub starting_capital: Option<f64>,
}

fn default_acceleration() -> f64 {
    1.0
}

impl ExecutionSettings {
    /// Build the [`ExecutionMode`] for this settings block.
    ///
    /// `live_trade` needs a venue router to actually submit orders; without one
    /// it builds an unconfigured router so live orders are rejected rather than
    /// silently falling back to paper.
    pub fn into_mode(self, router: Option<ManagerRouter>) -> ExecutionMode {
        let mut config = SimConfig::default();
        if let Some(v) = self.spread_bps {
            config.spread_bps = v;
        }
        if let Some(v) = self.slippage_bps {
            config.slippage_bps = v;
        }
        if let Some(v) = self.fee_bps {
            config.fee_bps = v;
        }
        if let Some(v) = self.starting_capital {
            config.starting_capital = v;
        }
        match self.mode.as_str() {
            "live_test" => ExecutionMode::LiveTest { config },
            "live_trade" => ExecutionMode::LiveTrade {
                router: router.unwrap_or_else(|| {
                    ManagerRouter::unconfigured(ManagerConfig::default())
                }),
            },
            "playback" => ExecutionMode::Playback {
                config,
                acceleration: self.acceleration,
            },
            other => panic!(
                "unknown execution mode {other:?}; expected live_test, live_trade, or playback"
            ),
        }
    }
}

impl ManagerEngine {
    /// Build an engine from YAML-loaded execution settings.
    ///
    /// Pass `Some(router)` when `mode` is `live_trade`; otherwise `None` is fine
    /// (playback / live_test never touch a venue).
    pub fn from_settings(settings: ExecutionSettings, router: Option<ManagerRouter>) -> Self {
        Self::new(settings.into_mode(router))
    }
}

Rationale: adds `ExecutionSettings` (YAML-deserializable with typed `mode` enum),
`ConfigError` (recoverable errors instead of panic), `into_mode()` (converts
settings -> `ExecutionMode`, returns `Result`), `from_yaml_str()` /
`from_yaml_file()` (loading helpers), and `ManagerEngine::from_settings()`
(returns `Result`, rejects missing live-trade router). Mode mapping:
`live_test`/`live_trade`/`playback`. Numeric fields are validated before use.

--------------------------------------------------------------------------------
How to use (example entry point — still to be written by caller):

use uets_manager::{ExecutionSettings, ManagerEngine};

let yaml = read_to_string("settings.yaml")?;
let settings = ExecutionSettings::from_yaml_str(&yaml)?;
settings.validate()?;
let mut engine = ManagerEngine::from_settings(settings, None)?; // None for playback/live_test

// then feed MarketEvents via engine.replay_events(...) for playback
